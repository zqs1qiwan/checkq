## 1. 比较范围

| 类别 | 对象 | 为什么纳入 |
|---|---|---|
| 直接竞品 | QD（qiandao） | 同做 HTTP 定时自动化，且有内容生态 |
| 直接竞品 | 青龙（qinglong） | 同做定时任务面板，脚本生态最强 |
| 间接替代 | 手工签到 / 浏览器插件 / 日历提醒 | 多数用户此刻的真实方案 |

| 不处理 | 放弃签到、接受漏签 | 沉默的对照组，选型时会被忽略 |

| 维度 | 事实 | 来源 |
|---|---|---|
| 自述定位 | "一个 HTTP 请求定时任务自动执行框架，base on HAR Editor and Tornado Server" | 项目 README |
| 核心形态 | Web 面板 + 模板/请求列表；用户挑模板、填参数、定时跑 | 项目 README |
| 上手方式 | 从 HAR 抓包生成请求，或直接使用现成模板 | 项目 README |
| 反爬能力 | 提供多套镜像分层：常规镜像（含验证码识别）、lite 镜像、ja3 镜像（TLS 指纹） | 项目 README 的镜像说明 |

**不能从 README 得出的结论**：模板总量、活跃用户数、实际维护频率——没有公开数据，本文件不猜。

## 4. 事实层对照（不含判断）

## 6. 维护规则

1. **何时更新**：竞品发布影响选型的版本（新增运行时、内置可视化、内容生态变化）时；否则每季度复核一次。
2. **怎么写**：只写能从公开来源核对的内容；每条标来源与访问日期；自述与实测分开标注。
3. **不写什么**：用户量、模板总量、营收、内部运营策略——没有公开来源就不写。
4. **过期处理**：超过 6 个月未复核的条目，在表头标注"待复核"，而不是直接沿用。
