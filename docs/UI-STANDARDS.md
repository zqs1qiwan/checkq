# CheckQ 界面与交互金标准（v0.5）

> 这份文档是"看得见、说得清"在产品表面的落地标准，也是评审时唯一的口径。
> 它合订并增补了 `docs/PRD.md` §6 的产品要求；**自 v0.5 起，新增或修改页面以本文为准**，与旧文冲突时按本文执行，并顺手把旧文改过来。
> 适用范围：`web/src` 下所有界面（首页、模板、编辑器、日志抽屉、设置、弹窗、菜单）。不适用于 wiki 用户文档的排版。

---

## 0. 怎么用

1. 动手前：读 §5 的 12 条契约，确认你的改动不违反其中任何一条。
2. 动手时：只用 §1 的令牌与 §2 的组件，不新造间距、圆角、颜色、字号。
3. 交付前：走 §12 的自查清单；能机械检查的交给 §11 的护栏。
4. 需要新组件：先证明现有组件表达不了（写一句理由），再按 §2 的契约新增，并补护栏检查。

**三条不可协商的原则**

- **一屏一件事**：用户打开这个页面要完成的那件事，必须在第一眼可做。
- **说人话**：界面不出现"实例""参数""解析""配置项"这类内部术语；错误必须给下一步。
- **不骗人**：状态、进度、结果都在界面上如实呈现；没连线、没跑到、被跳过，必须看得见。

| 字号 | `--fs-xs`…`--fs-2xl` | 11 / 12 / 13 / 15 / 17 / 20 px | 正文 13；表格 12；标题 20 |
| 间距 | `--sp-1`…`--sp-6` | 4 / 8 / 12 / 16 / 20 / 24 px | 只用这六档 |
| 图标 | `--icon-sm` / `--icon-md` / `--icon-lg` | 13 / 16 / 20 px | 行内 / 按钮 / 空状态 |
| 品牌标志 | `--brand-mark-bg` / `--brand-mark-fg` / `--brand-mark-dot` | `#0e5a63` / `#ffffff` / `#a7e7e9` | 徽章底色 / 勾 / Q 尾点；两主题共用 |

**禁止**：emoji 当图标、彩色药丸当状态、荧光色、渐变按钮、在组件里硬编码 `padding: 13px`。

## 2. 基础组件契约

| 组件 | 文件 | 契约 |
|---|---|---|
| 弹窗 | `components/Modal.jsx` | 原生 `<dialog>` + `showModal()`；`height: fit-content`；显式居中（`position: fixed; inset: 0; margin: auto`）；关闭态 `display:none`；Esc / ✕ / 点遮罩都能关；提交型弹窗保存成功后**自己关** |
| 菜单 | `components/Dropdown.jsx` | Popover API；在弹窗内必须 Portal 到该 `<dialog>` 里，否则被 `inert` 拦住；点击项后立即收起；触发器里的箭头必须用 `IconChevronDown` |
| 图标 | `components/Icons.jsx` | 统一 16×16 线性 SVG，`stroke-width` 1.8；禁止用文本字形（`▾ / ⋯ / ✕`）当图标；同排图标按钮按 32×32 盒子居中，`svg { display:block }` |
| 已有选项选择 | `components/GroupPicker.jsx` | 能用下拉列出的值不得只靠手输；当前值高亮、可清空、Esc 关闭、空态给一句事实 |
| 确认框 | `confirm.jsx` | 只用于破坏性操作；文案写明**对象与后果**；按钮顺序「取消 / 确认」；确认按钮用 `--fail` 描边，不用实心红 |
| 提示条 | `toast.js` | 5 秒自动消失；同屏最多 2 条；只用于"已保存/已删除/已复制"这类瞬时结果，不承载错误详情 |
| 表格 | `styles.css` + 各页 | 表头 sticky；数字 `tabular-nums`；任务行选择器必须 `tr:not(.group-row)`；行内操作不超过 3 个，多的进「⋯」 |
| 表单 | `styles.css` | label 在上、说明用 `title` 悬停，不写常驻副标题；即时校验用 `:user-invalid`；错误在字段下方一行 |
| 品牌标志 | `components/Logo.jsx` | 徽章 + 字标；顶栏 22px、登录 44px、加载 30px、空状态 38px；不拉伸、不改色、不重复拼写 |
| 调度 / 恢复探测 | `RecoveryFields.jsx` | 任务详情与编辑器调度弹窗共用；默认关闭；开启后才展开间隔/次数；暂停提示用 `.pause-note` |
| 状态 | `styles.css` | 小圆点 + 文字（成功/失败/超时/已取消/排队/运行中/已暂停/未启用）；不用彩色背景块 |
| 元信息 | `.meta` | 细竖线分隔；最多 4 段；超出折叠进「详情」 |

## 3. 页面骨架

- **顶栏**：桌面 = 品牌 · 主题 · 通知 · 文档 · 身份；≤640px = 品牌 / + / ⋯ / 设置 四控件单行，其余收进「更多」（`.mobile-only`）。顶栏任何控件同高、不换行。
- **工具条**：`.page-head` 分 `.toolbar-left` / `.toolbar-right`，组内不拆散；主操作在最右。
- **侧栏/抽屉**：运行抽屉宽 `min(520px, 100vw)`；打开时画布仍可见（这是"日志↔画布双向定位"的前提）。
- **编辑器**：左调色板、中画布、右配置面板；面板可折叠，折叠后画布占满。
- **空状态**：一句事实 + 一个动作（例："还没有任务。先演练一遍，30 秒看到一次成功运行。"）；只有未筛选的空列表才显示低对比度品牌水印。
- **登录页**：品牌区 + 登录卡两列（≤820px 单列）；品牌区只放标志、一句话价值主张与三条承诺；登录卡用显式 label，不堆营销信息。

## 4. 画布语义（v0.5 新增，服务于"图必须等于执行"）

| 元素 | 规则 |
|---|---|
| 节点 | 最小宽 160px；名称最多 2 行；类型色取自 `STEP_TYPES.color`；选中态用 `--sel-ring` |
| 出口 | `http` 标「成功 / 失败」，`condition` 标「真 / 假」，`foreach` 标「每项 / 结束」，其余单出口**不标文字** |
| 未连线 | 出口画空心小圆点 + 悬停提示"这一步之后没有下一步"；保存时进检查清单（**不阻止保存**） |
| 循环 | `each → … → next` 的循环体在画布上以虚线容器框住，标题"对每个…"；容器只是渲染分组，**不改 `nodes/edges` 数据** |
| 失败路径 | `failed` 边用 `--fail` 虚线；未接时该节点右上角出现失败角标 |
| 密度 | 首屏 `fitView`；≥60 节点默认折叠循环容器；提供"大纲视图"作为等价入口（键盘可完成建流程） |
| 定位 | 日志点「定位」→ 画布滚动到节点并 `focus-flash`；节点点「看日志」→ 抽屉滚到该步 |

## 5. 交互契约（12 条，新增页面必须全部满足）

1. **一页一主任务**：页面标题即该任务；说明性文字不常驻（`copy-audit` 会拦）。
2. **默认值先给**：新建流程自带 UA、超时、重试默认值，不填也能跑。
3. **渐进披露三层**：可见 → 展开 → 弹窗；高级项（代理、charset、cookieJar、重试参数）默认收起。
4. **保存语义分明**：画布自动保存（顶栏"未保存"点）；表单弹窗显式保存（主按钮最右）。
5. **危险操作**：二次确认 + 写明对象与影响；不做"可撤销"承诺（除非真的实现了恢复）。
6. **错误三段式**：`{对象}{动作}失败：{原因}。{下一步}`；必须给动作，或说明为什么没有动作。
7. **空状态必须有一个动作**：不允许只有一句"还没有"。
8. **加载分级**：>300ms 骨架屏；>2s 显示进度文字（"第 3/7 步"）。
9. **尊重取消**：用户跳过引导、关闭弹窗后，同一流程不再强推（除非有新触发）。
10. **键盘完整**：Esc 关、Enter 提交、Tab 顺序符合视觉、`Ctrl+S` / `Ctrl+Z` / `Ctrl+Y`；`?` 出快捷键表。
11. **图标与文案**：不用 emoji 当图标；按钮 = 动词 + 对象；状态 = 小圆点 + 文字。
12. **数字与时间**：等宽数字；绝对时间"今天 08:30 / 11-14 08:30"；相对时间只用于"3 分钟前"。

## 6. 文案金标准

### 6.1 硬规则

| 规则 | 说明 | 正例 | 反例 |
|---|---|---|---|
| 不写常驻说明 | 解释进 `title` 悬停 | 按钮「导入 HAR」`title="从浏览器导出的 HAR 文件里提取请求"` | 按钮下方一行"点击此处可导入 HAR 格式文件" |
| 一个概念一个词 | 术语表见 6.3 | 「任务」「模板」「变量」「步骤」「运行」「调度」「通知渠道」 | 同一处混用"流程/任务/实例/项目" |
| 错误可行动 | 三段式，含下一步 | 「任务「每日签到」运行失败：站点把请求跳到了登录页。下一步：更新 Cookie 后重跑。」 | 「请求失败 (status 302)」 |
| 不空喊"暂不支持" | 给边界或替代路径 | 「需要浏览器渲染的站点不在支持范围；可改用外部服务节点。」 | 「暂不支持」 |
| 危险动作用陈述句 | 说清删什么、影响谁 | 「删除任务「A」？它的 12 条运行记录会一起删除。」 | 「确定要删除吗？」 |
| 数字带口径 | 统计要说明范围与时间 | 「近 7 天 · 本机时间」 | 「成功率 82%」 |

### 6.2 错误文案模板

```text
{对象}{动作}失败：{人话原因}。{下一步}
```

- 原因必须来自可观测证据（状态码、断言名、超时、缺变量、凭据失效），不猜。
- 下一步只能是四种之一：**看某一步的响应 / 改某个变量 / 调整某条规则 / 重跑一次**。
- 没有可靠下一步时，写「暂时无法判断原因，请展开第 3 步的响应体」——这也算给动作。

### 6.3 术语表（界面统一用左列）

| 用 | 不用 |
|---|---|
| 任务 | 流程、项目、实例 |
| 模板 / 从模板创建 | 模板同步、模板实例 |
| 变量 | 参数、环境变量（除非指系统 env） |
| 步骤 | 节点（"节点"只在画布技术语境出现） |
| 运行 / 重跑 | 执行、触发一次 |
| 调度 | 定时器、cron（cron 只在填写表达式时出现） |
| 通知渠道 | 推送方式 |
| 凭据 | 密钥、token（具体值一律遮蔽） |

## 7. 状态、空态与反馈

- **首页概览**：任务和模板的总数放在对应标签。概览展示今日运行结果、每日汇总和下次调度，运行中与排队中分别计数。后台刷新失败时保留最后一次载入的数据。
- **连续日志**：打开时定位到最新运行，同次运行的步骤按执行顺序展示。工具栏可加载更早记录，保留当前阅读位置。加载失败时保留已显示的日志，并允许重试。调试详情随所选运行切换，失败提示和重试入口就地显示。
- **状态词表**：未启用 / 等待调度 / 排队中 / 运行中 / 成功 / 失败 / 超时 / 已取消 / 已暂停。界面不得自造同义词。
- **失败必须三件套**：状态点 + 一句话原因 + 一个入口（看日志/改变量）。只有状态点不合格。
- **运行中**：任务行显示进度（第 N/M 步）；>2s 才显示，避免闪烁。运行抽屉提供「停止运行」，取消后状态改为「已取消」，不伪装成失败。
- **排队中**：明确写"已在运行，本次会排队"，不要让用户以为点了没反应。
- **保存**：≤200ms 出现"已保存"；失败时保留用户输入并给出重试，且阻止这次运行，不能拿旧流程去跑。
- **通知**：站内通知与推送渠道分开呈现；推送失败要在任务详情里可见（不能只发出去就完事）。

## 8. 响应式与移动端

- **断点**：640px（顶栏四控件、工具栏 36px）、900px（编辑器侧栏折叠）。
- 在相同视口和批量模式下，展开或折叠任务组时各列表头保持原位。调度表达式过长时省略显示，悬停可看完整值。窄屏操作列固定在表格右侧。
- ≤640px 任务列表首屏必须直接看到"任务名 / 状态 / 下次调度"，不靠横向滚动。
- 移动端定位：**只读 + 三动作**（运行、看日志、改变量）；不提供画布编辑。
- 触摸目标 ≥44px；横向滚动只允许出现在表格内，且首列吸附。
- 200% 缩放不得出现整页横向溢出。

## 9. 可访问性

- 正文对比度 ≥4.5:1（用 `--text` / `--muted` 两档即可满足，别自造灰）。
- 焦点环必须可见（`--focus-ring`），键盘 Tab 顺序与视觉顺序一致。
- 运行状态变化用 `aria-live="polite"` 播报，不要每条日志都播报。
- `prefers-reduced-motion` 下关闭所有非必要动画。
- 表格必须有 `caption`（可 `sr-only`）；图标按钮必须有 `aria-label`。
- 键盘必须能完成"建流程 → 运行 → 看日志"主路径（大纲视图是这条路径的保障）。

## 10. 性能预算

| 项 | 预算 | 怎么测 |
|---|---|---|
| 首页首屏 | ≤1.5s（本地） | Performance 面板 |
| 画布拖动 | 100 节点 ≥50fps | 压力样本 |
| 日志抽屉 | 1 万行不卡 | 已有长日志样本 + `content-visibility` |
| 保存反馈 | ≤200ms 出现"已保存" | `ui-smoke` |
| SSE | 断线 3s 内重连并补齐当前运行 | 断网演练 |

超预算时先减渲染，不要先加缓存。

## 12. 新页面 / 改动的自查清单

- [ ] 第一眼能完成这个页面的主任务；主操作在最右且唯一。
- [ ] 只用了 §1 的令牌；没有新增硬编码尺寸、颜色、字号。
- [ ] 弹窗能 Esc / ✕ / 遮罩关闭；提交成功后自己关。
- [ ] 破坏性操作有二次确认，且写明对象与后果。
- [ ] 空状态有一句事实 + 一个动作。
- [ ] 错误文案满足三段式，且下一步是可执行动作。
- [ ] 状态用"小圆点 + 文字"，用词来自 §7 状态词表（自动停用显示「已暂停」并带原因）。
- [ ] 图标全部来自 `Icons.jsx`，没有 `▾ / ⋯ / ✕` 文本字形；同行图标按钮 32×32 居中。
- [ ] 键盘可完成主路径；焦点可见；图标按钮有 `aria-label`。
- [ ] 640px 与 200% 缩放下关键信息不被截断。
- [ ] 加载 >300ms 有骨架屏，>2s 有进度文字。
- [ ] 画布改动：出口标注、未连线提示、循环容器符合 §4；未改 `nodes/edges` 结构。
- [ ] 跑过 `verify-round`（或至少 `copy-audit` + `ui-smoke`）。
